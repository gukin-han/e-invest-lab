# 서비스 방향: 기업 변화 탐지기 (Financial Diff)

> 상태: 방향 채택 검토 (2026-08-09). 외부 제안 글("기업 변화 탐지기")과 현재 구현을 비교 분석한 결과와 단계 계획.
>
> 핵심 결론: 제안의 골격(변화 탐지, 결정적 신호 엔진, SignalEvent 1급 객체)은 채택하되, 진입 순서는 뒤집는다 — 제안은 재무제표 축부터 시작하지만, 우리는 이미 살아있는 기대(컨센서스) 축으로 첫 신호를 내보내고 재무 축을 뒤에서 채운다.

## 1. 현재 자산 인벤토리

| 도메인 | 보유물 | 제안 글 기준 역할 |
|---|---|---|
| market | 전 종목 일별 시세 5년 (337만 행, 매일 자동 수집) | Valuation 축의 분자. MarketSnapshot 상당 |
| research | 애널리스트 리포트 EPS 추정치 (컨센서스·리비전·trailing/forward PER) | Expectation change 축 — 제안 7번이 "가장 유용한 자산"으로 지목한 것 |
| disclosure | 공시검색→원문 인프라, 정정공시 폴백, 사업의 내용 수집(46개사), Offering 추출(성공률 95.7%) | Filing 계층 + 제안에 없는 차별 자산(아래 3절) |
| company | 전 상장사 등록부 + 섹터 분류 | Company 계층 |

파이프라인 원칙도 이미 제안과 합치한다: "raw 수집과 통계 후작업 분리, 수집 시점에 해석 금지"는 제안의 "deterministic 데이터 엔진이 신호를 만들고 AI는 설명만" 원칙과 같은 구조다. LLM은 추출(데이터화)에만 쓰고 있고 신호 판정에는 쓰지 않는다.

## 2. 제안 대비 갭 — 신호별 데이터 의존성

제안의 신호 7개를 데이터 의존성으로 분해하면 세 덩어리다.

| 신호 | 필요 데이터 | 현재 |
|---|---|---|
| ⑦ Improving+Cheap 의 Expectation 축 (Forward EPS 리비전) | 컨센서스 시계열 | 보유 |
| ⑦ 의 Valuation 축 (PER 저평가) | 시세 + EPS | 부분 보유 (아래 주의) |
| ⑤ Shareholder Return | 배당·자기주식·주식총수 | 없음 — 단, OpenDART 정형 API라 XBRL 정규화 난제 없음 |
| ①②③④⑥ (마진·ROIC·FCF·부채·성장가속) | 분기 재무제표 → TTM 파생지표 | 없음 — 최대 공사 (XBRL 정규화, 분기 standalone 변환, 연결/별도) |

주의 두 가지:

- **5년 PER 백분위는 지금 못 만든다.** 과거 각 시점의 EPS(확정 실적)가 필요한데, 보유한 실적 EPS는 리포트 요약표의 최근 2개년뿐이다. 초기 Valuation 축은 "forward PER 절대 수준 + 컨센서스 커버리지 내 상대 위치"로 단순화하고, 5년 백분위는 재무제표 축(사업보고서 EPS)이 채워진 뒤 승격한다.
- **커버리지 비대칭.** 컨센서스 축은 애널리스트가 커버하는 종목(수백 개)만 산다. "2,500개 전 종목 감시"라는 제안의 약속은 재무제표 축 없이는 불가능하다 — 이것이 재무제표 수집이라는 큰 공사의 정당성이고, 순서를 뒤로 미룰 뿐 생략할 수 없는 이유다.

## 3. 제안에 없는 우리 차별 자산

- **Offering 데이터 (제품·매출 구성).** 제안의 Company Diff 페이지는 숫자 변화만 보여주는데, "이 회사가 무엇으로 돈 버는가"가 붙으면 신호의 evidence 설명력이 달라진다 ("영업이익률 개선 — 주력 제품군 X 비중 확대와 동행"). 역방향 조회(제품→기업)는 Peer 정의의 기준으로도 쓸 수 있다 (같은 섹터가 아니라 같은 제품군이 진짜 Peer). Offering 전수 배치의 가치가 이 방향에서 정당화된다.
- **정정공시 처리 경험.** 제안 9번이 "데이터 경쟁력"으로 꼽는 정정공시 버저닝의 실무 함정(원본·정정본 목록화, 파일 없음 폴백)을 이미 통과했다. filing_number 보존 구조도 lineage 요구와 맞는다.
- **금융 서식 실증.** 제안 10번의 "금융주 MVP 제외"를 우리는 실측으로 확인했다 (Offering 1차에서 금융 4사 전멸 — 서식이 아니라 "제품 개념 부재"가 원인). 금융 제외는 채택하되, 근거는 선례가 아니라 이 실측이다.
- **MCP 공개 앱 계획과의 시너지.** 제안 6번의 자연어 스크리너("현금흐름 좋아지고 자사주 소각하는 싼 회사")는 자체 NLU를 만들 문제가 아니라, Change Screener 를 MCP 도구로 노출하면 LLM 클라이언트가 조건 변환을 대신한다. 기존 MCP + 인가서버 계획이 이 서비스의 배포 채널이 된다.

## 4. 채택 / 변형 / 기각

**채택**: 변화 탐지라는 제품 정의, SignalEvent 1급 도메인 객체, 결정적 신호 엔진 + AI는 설명만, 신호 발생시점 기록(Why now / Timeline), 금융 제외, 4화면 MVP(Change Radar / Company Diff / Change Screener / Watchlist), 과금은 데이터 열람이 아니라 감시 대행.

**변형**:
- 진입 순서 역전 — 제안의 MVP(재무 20분기 × 200~300사) 대신, 보유 자산인 기대 축으로 첫 신호를 먼저 낸다. 근거는 트레이드오프다: 재무 축부터 가면 XBRL 정규화라는 최대 리스크가 첫 화면보다 앞에 오고, 기대 축부터 가면 SignalEvent 도메인·Radar 화면·알림 루프를 실데이터로 먼저 검증한 뒤 재무 축이 같은 틀에 꽂힌다.
- Valuation 축 단계화 — forward PER 상대 위치로 시작, 5년 백분위는 재무 축 이후 승격.
- 자연어 스크리너는 자체 구현이 아니라 MCP 노출로.

**기각**: 없음 — 제안 골격은 현재 구조와 충돌하지 않는다.

## 5. 단계 계획

각 단계는 "새 신호 1개 이상이 실데이터로 켜진다"를 완료 조건으로 한다.

- **Phase 0 — SignalEvent 도메인 + 첫 신호 (보유 데이터만).**
  - SignalEvent(companyId, signalType, detectedAt, strength, previousState, currentState, evidence) 도입.
  - 신호 1: Estimate Revision — 종목×연도 컨센서스의 3개월 방향 (상향/하향/유지, 강도 = 변화율·표본).
  - 신호 2: Revision+Cheap — 상향 중인데 forward PER 가 커버리지 내 하위권.
  - Change Radar 화면 1개 (기존 대시보드 확장이 아니라 신규 첫 화면).
- **Phase 1 — Shareholder Return (일별 상장주식수 시계열 기반).**
  - 데이터: `daily_stock_prices.listed_share_count` (2026-08-09 백필 완료분). 이 시계열은 소각만 잡고 매입은 안 보이는데, 이는 제품 기준과 일치한다 — **소각만 주주환원으로 인정, 매입은 신호로 치지 않는다** (되돌릴 수 없는 환원만 계산).
  - 판정식: 계단 추출(전일 대비 감소) → 기간 누적 감소율. 단 **감자 오탐 방지** 필요 — 무상감자도 감소 계단을 만들며 이는 환원의 정반대 신호. 감소폭 크기·주가 재조정 동반 여부로 1차 구분, 확정 근거는 DART 감자/소각 공시를 계단의 사유 라벨로만 붙인다.
  - DART 주식총수현황·자기주식 API는 강등 — 주가치가 매입 보유량 가시화였는데 매입을 신호로 안 쓰므로. 배당(DPS·배당성향)은 별도 정형 API로 이 단계에서 수집.
- **Phase 2 — 재무제표 본공사 (최대 리스크 구간).**
  - 단일회사 전체 재무제표(분기) 수집 → FinancialFact → 누적→standalone 변환, 연결/별도, 정정 재계산 → DerivedMetric(TTM 마진·매출 YoY 가속·FCF·순차입/EBITDA·ROIC) → 신호 ①③④⑥② 순차 점등.
  - 대상: 비금융 × 컨센서스 커버리지 종목부터 → 전 종목 확장. 5년 PER 백분위 승격.
- **Phase 3 — 루프 완성.**
  - Change Screener(조건 조합 조회), Watchlist + 변화 알림(disclosure 이벤트 기반), Company Diff 페이지(신호 타임라인 + Offering 컨텍스트), MCP 도구 노출.

## 6. 첫 행동

Phase 0 의 첫 조각 하나만: **기존 `eps_estimates` 위에 "종목×연도 컨센서스의 3개월 리비전 방향" 계산 쿼리 1개** (신규 수집 없음, 조회 전용). 이 쿼리가 Estimate Revision 신호의 판정식 초안이 되고, 결과를 보고 SignalEvent 스키마를 확정한다.
