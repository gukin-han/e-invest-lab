# 애널리스트 리포트 EPS 수집 플로우 (작업 초안)

> 상태: spike 단계. 소스 탐침 완료(2026-08-02), 서식 탐침 진행 중.
>
> 목표: 증권사 리포트가 **명시한 EPS 추정치**를 종목별로 수집·축적. 컨센서스 평균·리비전 추이 같은 통계는 축적물 위의 **후작업** — 수집 시점엔 계산·해석하지 않는다 (사업보고서 raw 원칙과 동일). 단일 리포트 안의 2차 분석 결과는 가져오지 않는다.

## 전체 파이프라인

```
1. 목록 폴링 (한경 컨센서스, 신규 report_idx 감지)   ← "이벤트"의 실체 = 주기 폴링
2. PDF 다운로드
3. raw 저장 (PDF 원본 + 목록 메타)
4. EPS 추출 (요약 재무표에서, 회계연도별·실적/추정 구분)
5. 추정치 저장
─────────────── 여기까지 수집. 아래는 후작업 ───────────────
6. 통계 집계 (종목×연도 컨센서스, 리비전 추이)
7. 즐겨찾기 푸시 알림 (나중 — 로그인 유저별 관심 종목)
```

## 소스 탐침 결과 (한경 컨센서스, 2026-08-02)

- 목록: `/analysis/list?skinType=business` + `sdate`/`edate`/`now_page`/`pagenum`. 컬럼: 작성일·제목·작성자·증권사·목표주가·투자의견·첨부.
- **제목이 전부 `종목명(6자리코드)` 패턴** → 목록 단계에서 종목 매핑 결정적, `companies.stock_code` 조인 가능.
- PDF: `/analysis/downpdf?report_idx=N` 직다운로드. **텍스트 레이어 존재** (스캔본 아님) → `pdftotext -layout` 추출 가능.
- EPS는 리포트 첫 장의 요약 재무표에 존재: 연도 헤더(2024 / 2025 / 2026E / 2027E)로 실적·추정 구분. 매출액·영업이익·PER·목표주가 동반.
- 주의: 공식 API 없는 스크래핑 — 요청 간격 넉넉히(분 단위 폴링, 다운로드 간 지연), 개인 분석 용도 한정, 수집물 재배포 금지.

## 수집 원칙

1. **리포트가 명시한 값만** 수집한다. 없으면 없는 대로 (추측·보간 금지) — 사업보고서 추출 제1원칙 동일.
2. PDF 추출 대상은 **EPS만** (회계연도별, 추정 `E` 구분 포함). 목록에 이미 노출되는 메타(목표주가·투자의견)는 추출이 아니라 목록 수집으로 함께 저장 (공짜 명시값).
3. 통계는 수집 테이블 위의 조회/집계로만 — 수집 파이프라인에 통계 로직을 넣지 않는다.

## 스키마 초안

```
AnalystReport                          ← 목록 메타 (raw)
  report_idx      한경 리포트 식별자 (자연키, 재수집 방지)
  stock_code      제목에서 파싱한 6자리 코드
  company_name    제목에서 파싱한 종목명
  title, broker(증권사), authors, published_date
  target_price, opinion               ← 목록 명시값 (nullable)
  pdf_path                            ← 저장 루트 기준 상대 경로. NULL = 미다운로드(재실행 대상)

EpsEstimate                            ← 추출값
  report_idx      → AnalystReport
  fiscal_year     회계연도 (예: 2026)
  estimated       추정 여부 (연도 헤더의 E 표기)
  eps             명시값 (원)
```

## 서식 탐침 결과 (2026-08-04 · 3개 증권사)

| 증권사 | 요약표 서식 | EPS 라벨 |
|---|---|---|
| 한화투자증권 | 세로형 — 지표 행 × 연도 열 (`EPS  3,862  3,150  3,621  4,161`) | `EPS` |
| 상상인증권 | 가로형 — 연도 행 × 지표 열 (`2026E  12,955 … 11,704 …`) | `EPS` (헤더) |
| 메리츠증권 | 가로형 (2028E까지 5개년) | `EPS (원)`, 상세표엔 `EPS(지배주주)` |

- 공통 불변식: 연도 토큰(`20\d\d` + 선택적 `E`)과 EPS 라벨이 반드시 존재. 표가 숫자 정렬 텍스트로 깨끗하게 추출됨(`pdftotext -layout`).
- 함정: 리포트 뒤쪽 상세 재무제표·`12M fwd EPS` 등 EPS 언급이 여러 번 → **추출 대상을 첫 요약표로 한정**해야 함 (사업보고서 슬라이서와 동일한 "대상 영역 한정" 문제).

**판정 (잠정): 규칙 파서 2전략(세로형·가로형) + 실패 시 LLM 폴백.** 사업보고서와 반대로 규칙이 1차인 근거 — 이 표는 지표·연도·라벨의 관례가 강한 순수 숫자 표라 서식 분기가 유한하고(3/3 파싱 가능), 규칙 1차는 비용 0에 환각 자체가 불가능. 에스컬레이션 구조(가드 실패 → 상위 수단)는 Offering 추출 ADR과 동형이고, 3곳 표본이라 잠정 — 빌드 후 실패 리포트로 검증.

## PDF 저장 결정 (2026-08-05)

- **파일시스템 + DB 경로**: PDF 는 `research.pdf-storage.root` (기본 `./data/analyst-report-pdfs`, gitignore) 아래 `{yyyy}/{MM}/{report_idx}.pdf`, DB 에는 루트 기준 상대 경로만. EPS 파서(pdftotext)가 파일 경로를 그대로 소비하고 DB 는 메타만 들고 가볍게 유지. DB BLOB(덤프 비대, 임시 파일 우회)·객체 스토리지(의존성·스트림 우회) 대비 선택.
- **별도 유스케이스**: `POST /internal/analyst-reports/download-pdfs` 가 `pdf_path IS NULL` 인 리포트만 다운로드. 목록 수집과 분리 — 기존 수집분 자동 백필, 실패는 재실행으로 복구, 목록 수집이 다운로드 지연·실패에 안 물림.
- **상태는 pdf_path null 여부만**: 상태 기계 없음. 원천 실패(`ResearchSourceException`)는 건너뛰고 실패 수로 집계(요약 `(downloaded, failed)`), 다음 실행이 재시도. 디스크 실패는 국소 장애가 아니라서 실행을 중단시킴(`UncheckedIOException`).
- 다운로드 가드: 응답이 `%PDF` 매직 바이트로 시작하지 않으면(원천 에러 페이지) 저장하지 않고 원천 예외 — DART 비 zip 응답과 동일 패턴. 다운로드 간 1초 지연.
