# 애널리스트 리포트 EPS 수집 플로우 (작업 초안)

> 상태: spike 단계. 소스 탐침 완료(2026-08-02), 서식 탐침 진행 중.
>
> 목표: 증권사 리포트가 **명시한 EPS 추정치**를 종목별로 수집·축적. 컨센서스 평균·리비전 추이 같은 통계는 축적물 위의 **후작업** — 수집 시점엔 계산·해석하지 않는다 (사업보고서 raw 원칙과 동일). 단일 리포트 안의 2차 분석 결과는 가져오지 않는다.

## 전체 파이프라인

```
1. 목록 폴링 (한경 컨센서스, 신규 report_idx 감지)   ← "이벤트"의 실체 = 주기 폴링
2. PDF 다운로드
3. raw 저장 (PDF 원본 + 목록 메타)
4. EPS 추출 (요약 재무표에서, 회계연도별·실적/추정 구분)
5. 추정치 저장 (+ 같은 트랜잭션에 EPS_EXTRACTED 아웃박스 이벤트)
5-1. PDF 정리 (발행일 1년 지난 파일 삭제, 행은 보존)
─────────────── 여기까지 수집. 아래는 후작업 ───────────────
6. 통계 집계 (종목×연도 컨센서스, 리비전 추이)
7. 슬랙 알림 (아웃박스 릴레이 1분 주기 → 웹훅)
8. 즐겨찾기 푸시 알림 (나중 — 로그인 유저별 관심 종목)
```

## 소스 탐침 결과 (한경 컨센서스, 2026-08-02)

- 목록: `/analysis/list?skinType=business` + `sdate`/`edate`/`now_page`/`pagenum`. 컬럼: 작성일·제목·작성자·증권사·목표주가·투자의견·첨부.
- **제목이 전부 `종목명(6자리코드)` 패턴** → 목록 단계에서 종목 매핑 결정적, `companies.stock_code` 조인 가능.
- PDF: `/analysis/downpdf?report_idx=N` 직다운로드. **텍스트 레이어 존재** (스캔본 아님) → `pdftotext -layout` 추출 가능.
- EPS는 리포트 첫 장의 요약 재무표에 존재: 연도 헤더(2024 / 2025 / 2026E / 2027E)로 실적·추정 구분. 매출액·영업이익·PER·목표주가 동반.
- 주의: 공식 API 없는 스크래핑 — 요청 간격 넉넉히(분 단위 폴링, 다운로드 간 지연), 개인 분석 용도 한정, 수집물 재배포 금지.

## 수집 원칙

1. **리포트가 명시한 값만** 수집한다. 없으면 없는 대로 (추측·보간 금지) — 사업보고서 추출 제1원칙 동일.
2. PDF 추출 대상은 **EPS만** (회계연도별, 추정 `E` 구분 포함). 목록에 이미 노출되는 메타(목표주가·투자의견)는 추출이 아니라 목록 수집으로 함께 저장 (공짜 명시값).
3. 통계는 수집 테이블 위의 조회/집계로만 — 수집 파이프라인에 통계 로직을 넣지 않는다.

## 스키마 초안

```
AnalystReport                          ← 목록 메타 (raw)
  report_idx      한경 리포트 식별자 (자연키, 재수집 방지)
  stock_code      제목에서 파싱한 6자리 코드
  company_name    제목에서 파싱한 종목명
  title, broker(증권사), authors, published_date
  target_price, opinion               ← 목록 명시값 (nullable)
  pdf_path                            ← 저장 루트 기준 상대 경로. NULL = 미다운로드(재실행 대상)

EpsEstimate                            ← 추출값
  report_idx      → AnalystReport (자연키 참조, report_idx+fiscal_year 유니크)
  fiscal_year     회계연도 (예: 2026)
  estimated       추정 여부 (연도 헤더의 E/F 표기)
  eps             명시값 (원)
  extracted_at    추출 실행 시각 (진입점 캡처)

AnalystReport.eps_extraction_status    ← 추출 상태
  NULL=미시도 / EXTRACTED / NO_SUMMARY_TABLE / FAILED
  재추출 대상은 NULL·FAILED 만 — NO_SUMMARY_TABLE 은 "원래 없음" 확정
```

## 서식 탐침 결과 (2026-08-04 · 3개 증권사)

| 증권사 | 요약표 서식 | EPS 라벨 |
|---|---|---|
| 한화투자증권 | 세로형 — 지표 행 × 연도 열 (`EPS  3,862  3,150  3,621  4,161`) | `EPS` |
| 상상인증권 | 가로형 — 연도 행 × 지표 열 (`2026E  12,955 … 11,704 …`) | `EPS` (헤더) |
| 메리츠증권 | 가로형 (2028E까지 5개년) | `EPS (원)`, 상세표엔 `EPS(지배주주)` |

- 공통 불변식: 연도 토큰(`20\d\d` + 선택적 `E`)과 EPS 라벨이 반드시 존재. 표가 숫자 정렬 텍스트로 깨끗하게 추출됨(`pdftotext -layout`).
- 함정: 리포트 뒤쪽 상세 재무제표·`12M fwd EPS` 등 EPS 언급이 여러 번 → **추출 대상을 첫 요약표로 한정**해야 함 (사업보고서 슬라이서와 동일한 "대상 영역 한정" 문제).

**판정 (잠정): 규칙 파서 2전략(세로형·가로형) + 실패 시 LLM 폴백.** 사업보고서와 반대로 규칙이 1차인 근거 — 이 표는 지표·연도·라벨의 관례가 강한 순수 숫자 표라 서식 분기가 유한하고(3/3 파싱 가능), 규칙 1차는 비용 0에 환각 자체가 불가능. 에스컬레이션 구조(가드 실패 → 상위 수단)는 Offering 추출 ADR과 동형이고, 3곳 표본이라 잠정 — 빌드 후 실패 리포트로 검증.

## PDF 저장 결정 (2026-08-05)

- **파일시스템 + DB 경로**: PDF 는 `research.pdf-storage.root` (기본 `./data/analyst-report-pdfs`, gitignore) 아래 `{yyyy}/{MM}/{report_idx}.pdf`, DB 에는 루트 기준 상대 경로만. EPS 파서(pdftotext)가 파일 경로를 그대로 소비하고 DB 는 메타만 들고 가볍게 유지. DB BLOB(덤프 비대, 임시 파일 우회)·객체 스토리지(의존성·스트림 우회) 대비 선택.
- **별도 유스케이스**: `POST /internal/analyst-reports/download-pdfs` 가 `pdf_path IS NULL` 인 리포트만 다운로드. 목록 수집과 분리 — 기존 수집분 자동 백필, 실패는 재실행으로 복구, 목록 수집이 다운로드 지연·실패에 안 물림.
- **상태는 pdf_path null 여부만**: 상태 기계 없음. 원천 실패(`ResearchSourceException`)는 건너뛰고 실패 수로 집계(요약 `(downloaded, failed)`), 다음 실행이 재시도. 디스크 실패는 국소 장애가 아니라서 실행을 중단시킴(`UncheckedIOException`).
- 다운로드 가드: 응답이 `%PDF` 매직 바이트로 시작하지 않으면(원천 에러 페이지) 저장하지 않고 원천 예외 — DART 비 zip 응답과 동일 패턴. 다운로드 간 1초 지연.

## EPS 추출 결정 (2026-08-07)

- **텍스트 추출 = pdftotext 바이너리 직접 호출** (ProcessBuilder, `-layout`, 첫 2페이지). 탐침·실측이 전부 이 출력 기준이라 파서 규칙이 그대로 유효. PDFBox 는 레이아웃 보존이 달라 탐침 무효화, 별도 추출 서버는 정당화할 요구(파이썬 전용 능력·부하 격리)가 아직 없음. 어댑터 빈 생성 시 `pdftotext -v` 로 기동 가드 — 미설치 환경은 시작 시점에 실패.
- **포트 구성**: 유스케이스는 `EpsExtractor` 포트(경로 → 추출 결과) 하나만 본다. `infrastructure/pdf` 안에서 `PdfTextReader`(프로세스 호출) + `EpsSummaryTableParser`(표 해석) 합성 — 나중에 추출 수단이 바뀌어도 어댑터만 교체.
- **판정 3분류**: EPS 앵커 자체가 없으면 NO_SUMMARY_TABLE(확정, 재시도 안 함), 앵커는 있는데 못 읽으면 FAILED(재시도 대상), 성공이면 EXTRACTED + `eps_estimates` 저장. 저장과 상태 기록은 리포트 단위 한 트랜잭션.
- **파서 2전략**: 세로형은 EPS 라벨이 행 첫 토큰 + 위쪽 연도 헤더 행을 찾아 열 끝위치 근접 매칭(허용 오차 10자) — 사이드바 차트 축 숫자(80,000) 오염을 거리로 걸러냄. 가로형은 헤더 라벨 토큰 인덱스로 연도 행의 값 선택(열 위치 검산 동반). 최소 2개 연도 미만이면 실패.
- **저장 전 가드**: 회계연도는 발행연도 -3 ~ +5, 연도 중복 금지, 위반 시 저장 없이 FAILED.
- **실물 픽스처 4종**(`fixtures/research/eps-*.txt`, pdftotext 실제 출력 발췌): 세로형(한화, 음수 EPS), 세로형+사이드바 오염(LS, `EPS (원)` 라벨), 가로형(상상인), 산문 언급만(메리츠). known-violation(추정 플래그 고정 버그)으로 빨간불 확인 후 원복.
- 한계: 가로형 표가 있는데 파싱이 안 되는 경우 일부가 NO_SUMMARY_TABLE 로 분류될 수 있음(산문 오탐 방지와의 교환). 라이브 실측 분포로 재평가.

## 슬랙 알림 결정 (2026-08-17)

- 추출 성공(EXTRACTED)마다 `EpsExtractedEvent`(report_idx·종목·연도별 EPS 스냅샷)를 아웃박스에 발행 — 추정치 저장과 같은 트랜잭션 ([아웃박스 ADR](../adr/transactional-outbox.md)). NO_SUMMARY_TABLE·FAILED 는 발행 없음.
- **페이로드는 raw, 보강은 소비 측.** `EpsExtractedNotifyHandler` → `EpsNotificationComposer` 가 알림 시점에 리포트 메타(증권사·목표주가·투자의견), 같은 증권사의 직전 추출 리포트, **그 증권사를 뺀** 컨센서스(6개월), 최신 종가를 조회해 `EpsNotification` 을 조립 → `EpsNotifier` 포트 → `SlackEpsNotifierAdapter`(Incoming Webhook, `SLACK_WEBHOOK_URL`). 파생값(리비전·갭·PER)은 저장하지 않는다 — raw 두 테이블에서 언제든 재계산 (통계 후작업 원칙 동일).
- **핵심 지표는 "이번 리포트가 기대를 얼마나 바꿨나".** 기준 연도 = 첫 추정 연도(E). 첫 줄 시그널은 기준 연도 EPS 의 직전 대비 변화율로 — 10% 이상 강한 상향 / 3% 이상 상향 / ±3% 유지 / -3% 이하 하향 / -10% 이하 강한 하향, 직전 없으면 신규. 등급은 스캔용 라벨이고 숫자(리비전·컨센서스 갭)를 그대로 함께 보여준다 — 점수화하지 않는다.
- 메시지 순서: 시그널·종목·증권사 → 기준 연도 EPS(직전, 리비전, 컨센서스 갭) → 목표주가 변화·투자의견(원문)·현재가(기준 연도 PER) → EPS 경로(연도별, 전년 대비) → 리포트 링크. 위 세 줄만 봐도 상황이 읽히게.
- 원문 함정: 목표주가 `0` = 미제시 (표시·변화율 생략), 투자의견은 `Buy`/`매수` 등 표기가 섞여 있어 정규화 없이 원문 그대로 — "의견 변경" 신호는 정규화를 결정한 뒤.
- 컨센서스에서 자기 증권사를 빼는 이유: 알림 시점엔 이번 리포트가 이미 저장돼 있어 포함하면 자기 값이 평균을 끌어당겨 갭이 0 쪽으로 왜곡된다.
- 직전 리포트 판정: 같은 종목·증권사·EXTRACTED 중 발행일이 앞선 최신, 같은 날이면 report_idx 가 앞선 것 (한경 이중 게시는 리비전 0%로 표시됨).
- 어댑터는 재시도하지 않는다. 실패는 릴레이가 백오프(1분~12시간, 6회 후 DEAD)로 처리. URL 미설정도 같은 경로 — 백오프 창(약 15시간) 안에 URL 을 넣고 재기동하면 밀린 알림이 나가고, 넘기면 DEAD 로 남는다.
- 재추출 시 재발행 = 재알림 (at-least-once). 대량 재추출 전엔 유의.
- 라이브 확인 (2026-08-17): 6/29~6/30 백필 34건 + 재추출 1건 전부 SENT, 실패 0. HMM(LS증권 8/14 vs 7/31): 2026E 2,424 → 2,235 (-7.8%) → `[하향]`, 목표주가 30,000 유지.
